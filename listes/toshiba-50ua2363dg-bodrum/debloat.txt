# QUIRKS ON THIS FIRMWARE:
# - `cmd package set-home-activity` prints Success and changes nothing while the stock launcher is
#   still enabled: Home keeps resolving to com.google.android.tvlauncher. Install the new launcher,
#   confirm it starts, then disable the stock launcher — launcher/build-and-install.sh does this in
#   the right order and rolls Home back if it fails.
# - `dumpsys` can wedge on long uptimes ("Service dumps disabled due to hung system process"), which
#   silently disables three of tools/disable.sh's safety checks. A reboot clears it. Check that
#   `dumpsys package <pkg>` answers before disabling anything.
# - The kernel load average sits near 66 while 319%/400% of CPU is idle: the MStar SoC driver threads
#   (CEC, DISP, DMX, VMon_Task...) park in uninterruptible-D state and Linux counts them. Not a fault.
# - No microphone on the panel (no android.hardware.microphone) and an IR remote, so voice would come
#   from a phone or Nest speaker. That needs katniss: keep it if you use it. This owner does not.
# - com.google.android.marvin.talkback ships disabled on this unit; it is not listed below.
# - android.autoinstalls.config.vestel.malin is NOT listed: tools/disable.sh refuses it because the
#   package declares no permission block at all, so the TV_INPUT_HARDWARE check cannot be evaluated.
#   It stays enabled here; TVINPUT_ALLOW=1 would force it, which this owner chose not to do.
# - The stock launcher keeps dead tiles in its favourites row for packages disabled below
#   (Google Play Movies & TV); cosmetic, and moot once the launcher is replaced.
